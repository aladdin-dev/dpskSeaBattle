# Публикация игры на GitHub Pages

GitHub Pages — бесплатный статический хостинг GitHub. Приложению не нужен
Node.js на сервере: достаточно выложить `index.html`, `css/`, `js/`, `vendor/`
и `assets/`. HTTPS GitHub включает автоматически — это важно для WebRTC и
буфера обмена на телефонах.

Итоговый адрес будет таким:

```
https://ИМЯ_ПОЛЬЗОВАТЕЛЯ.github.io/ИМЯ_РЕПОЗИТОРИЯ/
```

Например: `https://ivanov.github.io/morskoy-boy/`.

> Репозиторий должен быть **публичным**, если вы пользуетесь бесплатным
> аккаунтом GitHub. Код игры всё равно полностью выполняется в браузере, а
> секретов в проекте нет.

## Вариант 1. Без командной строки, через сайт GitHub

Подходит для первой публикации.

1. Зарегистрируйтесь на [github.com](https://github.com).
2. Нажмите **New repository**.
3. Заполните:
   - **Repository name:** `morskoy-boy` (или другое короткое имя латиницей);
   - **Visibility:** `Public`;
   - не ставьте галочки «Add a README file», «Add .gitignore» и «Choose a
     license» — эти файлы уже есть в проекте.
4. Нажмите **Create repository**.
5. На странице пустого репозитория выберите **Add file → Upload files**.
6. Откройте папку `C:\Users\dondi\Vibecoding\DeepSeek` в Проводнике и
   перетащите в окно браузера **содержимое папки**, а не саму папку `DeepSeek`:
   - `index.html`
   - `assets`
   - `css`
   - `docs`
   - `js`
   - `vendor`
   - `tests`
   - `README.md`
   - `LICENSE`
   - `package.json`
   - `server.mjs`
   - `.gitignore`

   Важно: `index.html` должен оказаться в **корне** репозитория, а не внутри
   вложенной папки.
7. Внизу нажмите **Commit changes**.
8. Создайте пустой файл `.nojekyll`, чтобы GitHub Pages не обрабатывал сайт
   через Jekyll:
   - **Add file → Create new file**;
   - имя файла: `.nojekyll`;
   - оставьте содержимое пустым или поставьте один пробел — содержимое не важно;
   - **Commit changes**.
9. Откройте **Settings** репозитория → в левом меню **Pages**.
10. В блоке **Build and deployment**:
    - **Source:** `Deploy from a branch`;
    - **Branch:** `main`;
    - **Folder:** `/ (root)`;
    - нажмите **Save**.
11. Подождите 1–3 минуты и обновите страницу. Вверху появится ссылка
    **Your site is live at ...** — это и есть адрес игры.

После изменений файлов в репозитории GitHub Pages пересоберёт сайт
автоматически. Обычно это занимает 1–2 минуты.

## Вариант 2. Через командную строку

Так удобнее обновлять игру. Нужен установленный [Git](https://git-scm.com/).

Откройте PowerShell в папке проекта и выполните команды по одной.

### Первая публикация

```powershell
cd C:\Users\dondi\Vibecoding\DeepSeek

# один раз на компьютере: подставьте свои данные
git config --global user.name "Ваше Имя"
git config --global user.email "ваш-email@example.com"

git init
git add .
git commit -m "Морской бой: первая версия"
git branch -M main
```

Эти данные попадут в историю коммитов. Если Git на компьютере уже настроен,
две команды `git config` можно пропустить.

Создайте на GitHub пустой публичный репозиторий `morskoy-boy` (без README) и
скопируйте его HTTPS-адрес. Затем:

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/morskoy-boy.git
git push -u origin main
```

При первом `push` Git попросит войти в GitHub. В Windows удобно использовать
Git Credential Manager — он открывает окно входа в браузере. Пароль от аккаунта
вводить в терминал не нужно.

Затем включите Pages по инструкции из шагов 8–11 предыдущего варианта:
**Settings → Pages → Deploy from a branch → main → / (root) → Save**.
Файл `.nojekyll` уже лежит в проекте.

### Обновление игры в будущем

```powershell
git add .
git commit -m "Описание изменений"
git push
```

Через пару минут изменения появятся на сайте. Если браузер показывает старую
версию — обновите страницу с `Ctrl + F5` или откройте в приватном окне.

## Проверка после публикации

1. Откройте ссылку `https://ВАШ_ЛОГИН.github.io/morskoy-boy/`.
2. Нажмите **Создать игру** и дождитесь ID комнаты. Если облако PeerJS
   недоступно в вашей сети, приложение автоматически переключится на резервный
   сигнальный сервер — ID начнётся с `bsb-x-` или `bsb-w-`.
3. Откройте ту же ссылку во втором окне браузера (лучше в приватном) или на
   телефоне.
4. Нажмите **Присоединиться**, вставьте ID и подключитесь.
5. Расставьте флоты, нажмите «Флот готов — в бой» и сделайте несколько
   выстрелов.

Телефон и компьютер должны открывать **один и тот же HTTPS-адрес**. Локальный
`http://localhost:8080` с телефона не подойдёт: это адрес вашего компьютера, а
не сайта в интернете.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| `404` на главной | `index.html` лежит в корне репозитория, а не в подпапке. В Pages выбрана ветка `main` и папка `/ (root)`. |
| Сайт не обновился | Подождите 2–3 минуты, откройте **Actions** или **Pages** в настройках, обновите страницу с `Ctrl + F5`. |
| Стили не загрузились | Все папки `css/`, `js/`, `vendor/`, `assets/` загружены и сохранили структуру. |
| Комната не создаётся | Проверьте интернет. Облако PeerJS может быть заблокировано — приложение само попробует резервный сервер. Если не помогло, попробуйте другую сеть/VPN. |
| Второй игрок не подключается | Убедитесь, что он вставил ID целиком и что вкладка создателя комнаты не закрыта. |
| Нет соединения на мобильном интернете | Некоторые операторы и симметричный NAT блокируют прямое WebRTC. Попробуйте Wi‑Fi или другую сеть. |
| Не работает копирование | На HTTPS обычно работает; если браузер запретил буфер, выделите ID вручную. |

## Полезно знать

- GitHub Pages не запускает `server.mjs` и `npm start`. Это статический хостинг,
  и для этой игры сервер не нужен.
- Не загружайте в репозиторий `node_modules`, `.npm-cache`, `test-artifacts` и
  другие временные папки — они уже перечислены в `.gitignore`.
- Для собственного короткого адреса можно подключить домен в
  **Settings → Pages → Custom domain**, но для старта он не обязателен.
